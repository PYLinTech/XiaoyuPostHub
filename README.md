# XiaoyuPostHub

XiaoyuPostHub 是一个自建文件存储与分享系统，包含 Go 后端、React 前端和 PostgreSQL 数据库。

## 快速安装

中国大陆用户：

```bash
curl -fL 'https://raw.giteeusercontent.com/PYLinTech/XiaoyuPostHub/raw/main/install.sh' -o install.sh && chmod +x install.sh && ./install.sh
```

国际用户：

```bash
curl -fL 'https://raw.githubusercontent.com/PYLinTech/XiaoyuPostHub/refs/heads/main/install.sh' -o install.sh && chmod +x install.sh && ./install.sh
```

## 已实现功能

- 文件与文件夹管理：分片上传、断点续传、全平台 SHA-256 秒传、目录浏览、预览、重命名、用户隔离回收站和打包下载。
- 分享与直链：随机链接、可选密码和有效期、下载次数与流量限制、批量启停和重新配置；**取件码分享可自选有效期（含永久有效，由管理员开关控制）**，失效取件码可被回收再分配。
- 账户与权限：注册、邀请码、用户组（组级权限、配额与存储后端绑定）、用户禁用与密码重设；另含系统预设的**未登录访客（guest）用户组**（不可删除、不接受成员），用于给未登录访问配置配额。
- 管理功能：运行概览、全量文件与分享审核、系统审计、站点、下载策略和上传并发配置；另含**全局分享与取件码管理**（改期含永久、启停、解封、删除、一键释放失效取件码）、**在途上传会话管理**（直接取消并清理临时分片，无需等待过期），以及随调随生效的系统开关（允许永久取件码、邀请码有效期、单文件系统硬上限）。
- 站内消息：面向全体、用户组或用户投递，支持已读和删除状态。

上传任务由数据库按用户隔离保存。前端提供可折叠的上传任务面板，支持暂停、继续、删除和调整队列顺序；刷新页面或意外中断后可恢复任务。系统配置可调整分片大小（默认 8M）、单任务分片并发数和单用户任务并发数，并可发送测试分片验证反向代理请求体限制。

用户删除的文件和文件夹默认进入各自的回收站，可逐项恢复、永久删除或清空。删除与「永久删除」都只做用户侧标记：文件对用户不可见、不可恢复，但资源行与物理文件保留，供管理员审查与清理。**管理员限制的文件**（审核判定需保留/封禁）不可被用户「永久删除」「清空回收站」或保留期到期清理绕过，其物理清理由管理员在审核回收站执行；恢复时若目标位置已有同名条目会**自动改名恢复**（如 `文件 (1).ext`），不会因重名失败。回收站保留期限由系统管理员配置，默认 30 天；到期内容同样只做标记，不会自动物理删除。**配额口径**：回收站中的文件仍占用用户的存储配额（空间并未归还）；「永久删除」（含清空回收站与保留期到期）后释放。每日上传次数/流量按**自然日**（服务器本地时区当天零点起）统计，删除不会重置当日额度。**下载方向限额**（每日下载流量/次数）限制的是**下载者**：登录用户按其账号，未登录访问按来源 IP 各自识别为一个「用户」，统一使用系统预设**未登录访客（guest）用户组**绑定的配额方案；分享页/取件码/直链/文件页的下载均在创建下载计划或直链完整取流时计次计流量，事件只增不减（删除资源不会返还当日额度）。

取件码分享的有效期可自选（`0` = 永久）。取件码是否占用码空间由 `shares.pickup_code_live` 标记：**已停用/已过期/已删除/审核判定需删链**的取件码会被维护任务（每小时）与「清理失效取件码」入口释放，码空间可被重新分配（码值保留在行上供追溯）；重新启用时会复用空闲原码，若原码已被其它分享占用则自动换发新码并在界面明确提示。管理员可用「允许永久取件码」开关统一禁止永久码；永久码较多时用「一键释放失效取件码」腾出码位置。

文件内容保存为独立的物理对象（`storage_blobs`），多个资源可通过引用计数复用同一对象：全平台 SHA-256 秒传只增加引用，不再复制文件；覆盖上传替换对象后旧对象只降引用，引用归零的对象标记为待清理，物理删除只由管理员执行。**秒传的跨用户复用可在「系统配置」关闭**（关闭后只与本人已有的对象去重）：开启时按内容全局去重最省存储，但知道文件 SHA-256 与大小的用户即可复用他人对象（等于可读取该文件内容）；关闭后他人私有文件不可被领取。所有下载交付统一经由进程内的随机交付地址（`/dl/<id>`）：地址不包含资源标识、不落库、重启即失效，支持 Range 与断点续传；直链在生成时展示文件的 SHA-256 校验码，供使用者自行核对。

存储加密与交付策略由管理员在「系统配置」控制：新上传文件可选用 AES-256-GCM 分块加密存储——每个文件生成独立随机数据密钥（DEK），经部署密钥（`.env` 中的 `XPH_ENCRYPTION_KEYS`，支持多密钥轮换）包裹后存入数据库，**部署密钥丢失即加密文件永久不可恢复，务必离线备份**。加密文件的交付：分享页/文件页可选择由服务器实时解密输出明文，或改由浏览器端解密（每次请求现场生成临时 RSA 密钥对，服务端只下发用该公钥加密的密钥信封，仅 HTTPS 部署可用）；直链始终由服务器解密。分享页交付方式可选「本机中转」或「302 直跳第三方存储」——302 下加密文件同样直连第三方并随准备响应下发密钥信封、由浏览器解密（不降级）；多物理分片对象与预览、文件夹打包固定走本机中转。分享页对加密文件展示「已加密存储」标识。

存储后端由管理员在「存储管理」中登记（`storage_backends` 表），新上传默认写入「默认」后端；用户组可在「权限与配额」中绑定专属存储后端（`user_groups.storage_backend_id`），组内成员的新上传优先写入绑定后端（多组用户按组优先级取最高的已绑定组，与配额方案规则一致），未绑定则回退全局默认；绑定后端被停用时上传明确失败（不静默改写位置）。管理员切换组绑定时自动创建存储迁移任务，把该组成员的存量对象搬到新后端；加密对象在迁移中由服务端解密后以新随机密钥重新加密（因此迁移要求部署已配置加密密钥 `XPH_ENCRYPTION_KEYS`，未配置时加密对象的迁移任务会失败）。停用后端只阻止新写入：其上的存量对象仍可正常读取、迁移与删除。当前支持本机存储、**S3 兼容对象存储**（AWS S3 / MinIO / Cloudflare R2 / 阿里云 OSS / 腾讯云 COS，手写 SigV4 签名，无重型 SDK 依赖）与 **123 云盘开放平台**。凭据全部来自部署配置（`.env` 中的 `XPH_S3_ACCESS_KEY_ID` / `XPH_S3_SECRET_ACCESS_KEY`、`XPH_PAN123_CLIENT_ID` / `XPH_PAN123_CLIENT_SECRET`，属于敏感配置，不入库、不下发浏览器），endpoint/bucket/根目录 ID 等非敏感参数在管理界面填写。123 云盘特点：上传走官方 V2 接口（≤1GB 单步、≤10GB 分片；上传前先落本机中转文件计算 MD5，完成后立即清理，请确保临时目录有足够磁盘空间）；`access_token` 30 天有效且同账号最多 3 个并存（多实例部署时注意该限制），由服务端自动缓存续期（401 自动刷新重试一次、429 指数退避）；下载使用临时地址并透传 Range。123 云盘直链支持 **URL 鉴权**：在存储后端配置里开启「直链鉴权」并填写 123 云盘直链管理「鉴权管理」中的密钥**与账号 ID（个人中心可见，只能手填）**，服务端按官方开发指引示例为直链签名 `auth_key`（`timestamp-rand-uid-md5(URI-timestamp-rand-uid-密钥)`；URI 取解码后的请求路径，uid 取账号 ID，有效期与直链有效期一致），防止直链被他人盗用。**uid 不能从直链地址推断**：官方示例的直链域名是 `vip.123pan.com`（首段不是 uid），自定义直链域名下首段更是站点自己的前缀——猜错会让云盘 CDN 判为签名不符并直接返回 403，因此开启鉴权时未填写账号 ID 会明确报错而不是生成注定被拒的地址。密钥只保存在服务端、不回传浏览器（编辑时留空即沿用原值）；本机中转上游按「额度偏好」走直链通道时用的是同一套签名，且每次重开读取流都会按当前时间重新签名（长下载、断点续传跨过有效期也不会被拒）。对象存储与网盘在启用直链能力（S3 预签名 / 123 直链空间）后可参与「302 直跳」交付；未启用、或对象被拆为多个物理分片时自动降级本机中转（单个直链只能表达一个物理对象，无法表达分片）——因此 302 的覆盖范围与「新上传分片大小」相关。**123 云盘的「直链流量」与「自用下载流量」是两份独立额度**，在 123 后端配置里分成两组相互独立的设置：
① **额度偏好**——「分享优先使用」与「直链优先使用」都默认「自用下载流量」，只决定**本机中转时服务端从 123 取内容**走 `download_info`（自用额度）还是 `direct-link`（直链额度）；
② **交付方式**——默认「优先本机中转」，可改为「优先302连接」：此时分享页/文件页的明文文件由浏览器直连 123（消耗直链流量，需站点交付策略为 302），加密文件与多分片对象仍走本机中转。
**直链能力由设置推导，没有独立总闸**：只要交付方式选 302、或任一额度偏好选直链流量，加载后端时就会自动为存储根目录启用 123 云盘侧的直链空间（幂等，只开不关）；全部选自用且交付方式为本机中转时不做任何平台调用。
另有「**自用与直链可在异常时互相切换**」开关（**默认关闭**）：关闭时严格使用所选通道（「优先」即「始终」），不可用直接报错、不消耗另一份额度，便于判断额度是否用完；开启后才会自动改用另一条通道——**取址失败与取数被拒（401/403，例如直链鉴权签名不被接受）两条路径都覆盖**，避免直链坏掉把本机中转一起带走（切换发生在读取阶段，下载不中断）。
**站内直链 `/d/` 始终由本机中转交付**：对外只暴露一个固定地址，且必须交付用户可用的明文内容（第三方地址是临时的、加密对象在其上仍是密文），因此「直链优先使用」只影响服务端取内容的额度通道，不改变交付方式。分享页 302 交付加密对象时随准备响应下发密钥信封，由浏览器拉取密文后解密（不降级）；文件页与预览固定中转，加密对象由服务器实时解密或经信封在浏览器端解密。

**分片存储**（强制，不可关闭）：上传对象一律按「新上传分片大小」（默认 64MiB，必须是加密块 4MiB 的整数倍）切成多个独立物理条目；分片与加密天然兼容——分片边界与加密块对齐，每片可独立随机读取，Range、预览与断点续传在「分片 + 加密」对象上同样可用。存量未分片对象保持可读，可通过「维护任务 → 重新分片」按目标粒度重写。

**完整性校验的位置**：服务端**不做交付前校验**（完整读一遍再回放等于把文件读两遍，对远端后端还会使出站流量翻倍），完整性由两端保证——上传时服务端在写入过程中流式计算 SHA-256 并与前端声明的哈希比对（零额外 IO，不一致直接失败、不会落库）；接收时浏览器下载/解密完成后按 `X-XPH-Content-SHA256` 响应头（或准备响应中的 `sha256`）自行校验，不一致拒绝保存并提示重试。加密文件的 302 直连同样由浏览器解密后校验。

**停用或更换后端不会删除任何文件**：已有对象始终按其登记的后端读取。物理层面的搬运与清理由管理员的「维护任务」执行（后台排队、进度可见），共五个选项：**孤立文件 / 加密 / 解密 / 分片 / 迁移**。除迁移外都分两步：先「开始扫描」得到命中清单（不改动任何数据），确认清单后再点「执行」；**清理孤立文件是唯一会真正删除文件的入口**，有二次确认。系统不做任何自动清理：所有清理任务都只由管理员手动发起，后台循环仅做用户侧标记、删除物理文件。**迁移**由管理员选定原位置与新位置后直接执行，搬移成功后删除原位置的对象。维护任务先写新对象、更新数据库、再删旧对象：旧对象删除失败会让任务项标记失败并可安全重跑（幂等），单项异常被就地捕获不会影响服务；进程重启会把中断的任务标记为失败，可重新发起。123 云盘后端的「删除」是**移入平台回收站**（平台对已删除或不存在的 ID 均返回成功，天然幂等；多分片对象按每批 100 个批量删除，避免逐片调用触发限流）；回收站中的文件仍占用云盘空间，且平台不开放彻底删除接口，需要立即释放空间时请到 123 云盘客户端清空回收站。

管理员审查页按上传任务分页展示全部用户文件（含用户已彻底删除的内容），并保留任务内文件树的勾选联动；支持按 ID、文件名或用户名筛选、批量下载、通过或驳回、删除及拉黑。管理员删除的文件进入受限回收站，用户可见但不能恢复；撤销处置时会在文件仍存在的情况下自动还原。物理删除只由管理员执行（审核回收站清理）。覆盖上传、用户彻底删除与管理员审核处置都会追加写入 `file_moderation_history`；被拉黑的文件不能被覆盖上传替换，也不会通过秒传复用。分享审查支持批量预览渲染内容或源码、删除及封禁链接。所有审核结果都会写入用户站内消息和系统审计日志。创建直链时会展示文件的 SHA-256 校验码，直链交付不做交付前全量校验。

审核持久化只使用 `file_moderations` 与 `share_moderations`。旧审核表仅由数字迁移 SQL 删除，后端启动过程不执行或兼容任何数据库迁移。

安装或更新时，`install.sh` 从目标 Docker 镜像提取该版本的迁移助手；助手再从同一镜像读取 `migrations` 中的数字 SQL，并按顺序执行尚未记录的文件。因此后端程序、迁移助手与数据库变更始终来自同一个发布镜像。

**迁移编写规范**（升级是停机窗口：`install.sh` 先停服务再迁移，所以所有迁移一律在单事务内执行）：

- 每个文件在单事务中执行（失败整文件回滚、不登记、可重跑），因此文件内部语句必须幂等（`IF NOT EXISTS` / `ON CONFLICT` / 先 `DROP ... IF EXISTS` 再 `ADD`）。
- 加列可直接执行：PostgreSQL 对"常量默认值"是轻量元数据操作，不重写表。
- 加约束直接 `ADD CONSTRAINT` 一次成型：停机窗口没有读写竞争，不需要 `NOT VALID` + `VALIDATE CONSTRAINT` 的两步写法。
- 建索引直接 `CREATE INDEX IF NOT EXISTS`：单遍扫描比 `CONCURRENTLY` 更快，且失败随事务回滚，不会留下 `indisvalid=false` 的无效索引。**不使用 `CREATE INDEX CONCURRENTLY`**——它不能在事务块内执行，而本工具链一律把迁移包在事务里（`CREATE INDEX CONCURRENTLY cannot run inside a transaction block`）。若将来改为不停机升级，需要先给迁移助手加回非事务执行通道，并同时处理无效索引的清理（`DROP INDEX CONCURRENTLY IF EXISTS` 前置）。
- 结构变更与数据回填尽量拆分为独立迁移文件：停机窗口下这不再是为了缩短锁时间，而是缩短单次失败面、便于定位与重跑。

## 目录

- `backend/`：Go API 与业务逻辑。
- `frontend/`：React 用户界面。
- `migrations/`：按数字顺序执行的 PostgreSQL 迁移 SQL。
- `deploy/`：Docker 镜像与 Compose 配置。
